# WebGPU: Immediates

> **Report Week:** 2026-W37 | **Milestone:** Chrome 150 | **Category:** Enabled by default

## Overview

Functionality added to the WebGPU spec after its first shipment in a browser.

Adds a new immediate address space in WGSL and a setImmediateData() method on render pass, compute pass, and render bundle encoders that allows passing small amounts of frequently-updated data directly to shaders without creating GPU buffer objects or bind groups. This is particularly useful for applications that need to update per-draw parameters such as object indices, material indices, or transformation matrices every draw call, enabling significant performance improvements by avoiding buffer and bind group management overhead.

## Ecosystem Status

- **Momentum:** High (190 points)
- **Standards Alignment:** Multi-Engine Consensus
- **Sentiment:** Positive
- **Executive Take:** WebGPU Immediates brings standard push constant/root constant capabilities to the web, enabling the `immediate` WGSL address space and `setImmediateData()` on pass and bundle encoders without GPU buffer or bind group overhead. Shipped by default in Chrome 150 after extensive design within the W3C GPU for the Web working group, the feature represents a key performance milestone for reducing per-draw CPU bottlenecks. Broad cross-engine consensus exists across Google, Apple, and Mozilla, with CTS test suites actively expanding to align all engine implementations.

### Recommendations
- Actionable Advice: Adopt Immediates via feature detection using `navigator.gpu.wgslLanguageFeatures.has('immediate_address_space')` while keeping a standard uniform buffer fallback for unsupported browsers. Restrict usage strictly to small, high-frequency payloads (under the 64-byte minimum budget) and keep bulkier uniform or array data in traditional buffers.
- Shipping enabled by default in Chrome 150. Developers can begin adopting in production with progressive feature detection.
- Standards Activity (WebKit): Latest discussion from @shaoboyan091: "Thanks!..."
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
