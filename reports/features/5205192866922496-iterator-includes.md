# Iterator Includes

> **Report Week:** 2026-W38 | **Milestone:** Chrome 154 | **Category:** Enabled by default

## Overview

A TC39 proposal to allow the developer to ask whether an iterator yields a given value. Analogue to \`Array.prototype.includes\`.

## Ecosystem Status

- **Momentum:** High (286 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** Iterator Includes (\`Iterator.prototype.includes\`) is a Stage 3 TC39 proposal that brings parity with \`Array.prototype.includes\` to JavaScript's iteration protocol, utilizing the \`SameValueZero\` comparison algorithm. Chromium has completed its intent to ship enabled by default starting in Chrome 154, marking the first major engine rollout. While Mozilla Gecko (Bug #2025773) and WebKit JavaScriptCore (Bug #310698) actively track implementation, broad cross-engine baseline support is still forming.

### Recommendations
- Actionable Advice: Teams should not assume ubiquitous native availability in production yet and should continue relying on polyfills (such as \`core-js\`) or lightweight \`some()\` fallbacks for backwards compatibility. For Chromium-targeted environments like modern Electron or Node.js versions incorporating V8 milestone 154, the method can be safely adopted to simplify iterator consumption pipelines.
- Shipping enabled by default in Chrome 154. Developers can begin adopting in production with progressive feature detection.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
- Verified community discussion on Hacker News: "C++ ranges/views vs. Rust iterator" (2 points, 1 comments).
