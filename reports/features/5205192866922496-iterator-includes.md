# Iterator Includes

> **Report Week:** 2026-W42 | **Milestone:** Chrome 154 | **Category:** Enabled by default

## Overview

A TC39 proposal to allow the developer to ask whether an iterator yields a given value. Analogue to \`Array.prototype.includes\`.

## Ecosystem Status

- **Momentum:** Emerging (footprint 120 points, ranked against this week's features because too few have an earlier number to work out a change)
- **Standards Alignment:** Multi-Engine Consensus
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** Iterator.prototype.includes has advanced to Stage 3 within TC39 and shipped enabled by default in Chrome 154, providing an ergonomic, memory-efficient way to check for values without allocating intermediate arrays or exhausting infinite sequences. Engine consensus is solid across all major vendors, with implementation progressing swiftly across Gecko and JavaScriptCore. The feature effectively closes a long-standing parity gap between Array convenience methods and native Iterator helpers.

### Recommendations
- Actionable Advice: Teams can begin leveraging Iterator.prototype.includes today by pairing it with core-js polyfills or defensive method-existence checks in data-processing pipelines. Unpolyfilled production deployments should continue using Iterator.prototype.some or traditional generator loops until Safari ships unflagged support.
- Shipping enabled by default in Chrome 154. Developers can begin adopting in production with progressive feature detection.
- Strong multi-vendor alignment across Chromium, Gecko, and WebKit indicating high likelihood of eventual web baseline.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
