# Iterator Includes

> **Report Week:** 2026-W45 | **Milestone:** Chrome 154 | **Category:** Enabled by default

## Overview

A TC39 proposal to allow the developer to ask whether an iterator yields a given value. Analogue to \`Array.prototype.includes\`.

## Ecosystem Status

- **Momentum:** Moderate (+70 points since 2026-10-12; footprint 190 points)
- **Standards Alignment:** Multi-Engine Consensus
- **Sentiment:** Positive
- **Executive Take:** Iterator.prototype.includes bridges a long-standing ergonomics gap in JavaScript by allowing developers to lazily check whether an iterator yields a given value without converting it to an array. Championed through TC39 Stage 3, the feature has achieved unanimous engine consensus and shipped enabled by default in Chromium 154 and Firefox 154. With WebKit implementing support in Safari Technology Preview release notes, the API is rapidly approaching full cross-browser interoperability.

### Recommendations
- Actionable Advice: Web development teams can adopt the method immediately in modern environments by pairing native calls with a core-js polyfill or a fallback check on Iterator.prototype.includes. When consuming it, developers should ensure offset parameters are non-negative integers to avoid throwing unexpected RangeError exceptions.
- Shipping enabled by default in Chrome 154. Developers can begin adopting in production with progressive feature detection.
- Strong multi-vendor alignment across Chromium, Gecko, and WebKit indicating high likelihood of eventual web baseline.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
