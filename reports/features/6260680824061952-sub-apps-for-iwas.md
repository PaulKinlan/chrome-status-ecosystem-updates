# Sub apps for IWAs

> **Report Week:** 2026-W37 | **Milestone:** Chrome 150 | **Category:** In developer trial (Behind a flag)

## Overview

Sub apps allow developers to create multiple apps under a single Isolated Web App ([IWA](https://chromeos.dev/en/web/isolated-web-apps)) installation. Each Sub app has its own distinct name, icons and OS integrations. 

Sub apps appear on the desktop shelf with a distinct identity from the parent IWA, offering separate OS capabilities, such as file type association. This allows a single software package to present different, isolated functionalities to the user while maintaining a single, unified IWA install and update process. 

There are three new enterprise policies available to control the Sub apps API:

- [DefaultSubAppsWithoutPromptsSetting](https://chromeenterprise.google/policies/#DefaultSubAppsWithoutPromptsSetting) specifies globally (for all IWAs) if user permission prompts are required to install Sub apps. The policies below can override this default.

- [SubAppsWithoutPromptsAllowedForOrigins](https://chromeenterprise.google/policies/#SubAppsWithoutPromptsAllowedForOrigins) specifies a list of IWA URLs that can add or update Sub apps without user permission prompts. 

- [SubAppsWithoutPromptsBlockedForOrigins](https://chromeenterprise.google/policies/#SubAppsWithoutPromptsBlockedForOrigins) specifies a list of IWA URLs that can add Sub apps with user permission prompts only.

### Motivation

Without this API developers are forced into splitting the application into separate ones which complicates distribution or bundle everything into a single huge application that can potentially confuse users.

## Ecosystem Status

- **Momentum:** High (120 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Neutral
- **Executive Take:** The Sub Apps API is an incubation within the WICG tailored specifically for Isolated Web Apps (IWAs), enabling a single packaged Signed Web Bundle to install and manage distinct sub-applications with individual OS integrations like file associations and shelf identities. While Chromium is actively progressing the feature alongside enterprise management policies, it is not part of the standard web runtime and remains scoped strictly to IWA environments. Consequently, non-Chromium browser engines currently have no public signals or implementation plans.

### Recommendations
- Actionable Advice: Teams targeting enterprise ChromeOS or managed desktop environments using Isolated Web Apps should test sub-app registration behind developer flags using the `window.subApps` API. Developers building general-purpose PWAs for the open web should avoid architecting around this API, as it requires signed IWA contexts and lacks cross-browser availability.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
