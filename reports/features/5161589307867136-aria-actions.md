# aria-actions

> **Report Week:** 2026-W37 | **Milestone:** Chrome 151 | **Category:** Enabled by default

## Overview

Support aria-actions attribute. 

There is a common UI pattern where secondary actions are placed within composite interactive widgets. The aria-actions attribute allows us to expose these secondary action buttons directly for improved discoverability.

### Motivation

Many common UI patterns today involve the concept of "secondary actions", such as the close button on a tab. AT discovery of these related actions is a common pain point, for example, when a screen reader user focuses on a tab, they should be made aware of any associated controls, such as the close button.

## Ecosystem Status

- **Momentum:** High (220 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Positive
- **Executive Take:** The `aria-actions` attribute addresses a long-standing accessibility hurdle by allowing composite interactive widgets (such as tabs or listbox items) to expose secondary action controls directly to assistive technologies. Shipping enabled by default in Chrome 151, the API enjoys strong consensus across the W3C ARIA Working Group and browser vendors. Because it is purely additive and enhances discoverability without changing underlying keyboard contracts, it introduces zero backward-compatibility risk.

### Recommendations
- Actionable Advice: Web development and design system teams can immediately start adopting `aria-actions` as a progressive enhancement on composite widgets. Ensure associated actions remain conventionally keyboard-accessible as fallbacks for legacy browsers and screen readers.
- Shipping enabled by default in Chrome 151. Developers can begin adopting in production with progressive feature detection.
