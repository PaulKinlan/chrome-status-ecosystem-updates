# aria-actions

> **Report Week:** 2026-W39 | **Milestone:** Chrome 151 | **Category:** Enabled by default

## Overview

Support aria-actions attribute.   There is a common UI pattern where secondary actions are placed within composite interactive widgets. The aria-actions attribute allows us to expose these secondary action buttons directly for improved discoverability.

### Motivation

Many common UI patterns today involve the concept of "secondary actions", such as the close button on a tab. AT discovery of these related actions is a common pain point, for example, when a screen reader user focuses on a tab, they should be made aware of any associated controls, such as the close button.

## Ecosystem Status

- **Momentum:** High (110 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Positive
- **Executive Take:** The \`aria-actions\` attribute bridges a longstanding parity gap with native mobile accessibility by letting elements reference secondary interactive controls—such as close buttons inside tabs or action buttons inside list options. With Chrome enabling it by default in milestone 151 and Firefox having already rolled out platform mappings, engine consensus is exceptionally strong across the W3C ARIA Working Group. The API substantially improves screen reader discoverability in complex composite widgets without requiring clumsy keyboard tab navigation workarounds.

### Recommendations
- Actionable Advice: Teams maintaining complex interactive widgets (tabs, treeviews, cards, or custom listboxes) can begin adopting \`aria-actions\` as a progressive enhancement today, ensuring fallback keyboard focus order remains intact while assistive technology and browser mappings fully saturate.
- Shipping enabled by default in Chrome 151. Developers can begin adopting in production with progressive feature detection.
- Standards Activity (WebKit): Latest discussion from @bkardell: "In the triage meeting today we decided to propose that we add a support label here and close the issue in a week..."
- Standards Activity (Mozilla): Latest discussion from @jcsteh: "Retrospectively: I'm proposing a position of positive. We believe this is important in order for assistive technology users to be able to efficiently ..."
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
