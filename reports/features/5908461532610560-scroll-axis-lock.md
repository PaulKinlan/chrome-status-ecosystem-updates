# scroll-axis-lock

> **Report Week:** 2026-W39 | **Milestone:** Chrome 153 | **Category:** Enabled by default

## Overview

scroll-axis-lock is a CSS property that authors can use to instruct browsers not to constrain a user's scrolling gesture to one axis.  Web browsers often "lock" a user's scrolling gesture to a single axis when that gesture starts with significantly more movement in one axis than in the perpendicular axis. In many cases, this behavior improves the user's experience by avoiding accidental scrolls along the perpendicular axis when the user's intent was to scroll only one axis. However, in cases where an author wishes their element to always be diagonally scrollable, this locking behavior forces the user to start their gesture at an angle that doesn't trigger the locking, often not in alignment with the author's intended user experience.

- **Sentiment:** Positive
- **Executive Take:** The \`scroll-axis-lock\` property introduced in CSS Overflow Module Level 5 addresses a longstanding pain point by allowing authors to opt out of browser 'railing' heuristics in favor of smooth, immediate diagonal panning. Shipped by default in Chromium 153, the specification has received a positive review from the W3C TAG and is gaining traction across standards bodies. While Gecko and WebKit have not shipped it yet, both have logged tracking bugs and initiated discussions with generally receptive stances.

### Recommendations
- Actionable Advice: Teams building 2D panning, matrix snapping, or canvas interfaces should adopt \`scroll-axis-lock: none\` today as a progressive enhancement. Because non-supporting browsers simply ignore unknown CSS properties and retain their default axis-locking heuristics, applying it incurs zero regression risk.
- Shipping enabled by default in Chrome 153. Developers can begin adopting in production with progressive feature detection.
