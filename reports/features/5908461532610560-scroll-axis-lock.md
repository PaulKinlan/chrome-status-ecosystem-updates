# scroll-axis-lock

> **Report Week:** 2026-W40 | **Milestone:** Chrome 153 | **Category:** Enabled by default

## Overview

scroll-axis-lock is a CSS property that authors can use to instruct browsers not to constrain a user's scrolling gesture to one axis.  Web browsers often "lock" a user's scrolling gesture to a single axis when that gesture starts with significantly more movement in one axis than in the perpendicular axis. In many cases, this behavior improves the user's experience by avoiding accidental scrolls along the perpendicular axis when the user's intent was to scroll only one axis. However, in cases where an author wishes their element to always be diagonally scrollable, this locking behavior forces the user to start their gesture at an angle that doesn't trigger the locking, often not in alignment with the author's intended user experience.

## Ecosystem Status

- **Momentum:** High (339 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Positive
- **Executive Take:** Defined in CSS Overflow 5, scroll-axis-lock allows authors to disable default browser scroll-railing heuristics to enable immediate, freeform diagonal scrolling in 2D scrollers such as maps, infinite canvases, and gesture-driven UI components. Chrome shipped the property enabled by default in Chrome 153 following a satisfied W3C TAG review. Cross-engine consensus is robust: WebKit is actively implementing macOS and iOS support under preview tracking, while Mozilla is triaging imported web-platform-tests with an open supportive posture.

### Recommendations
- Actionable Advice: Teams building 2D panning UIs, schematics, or canvas-based apps should adopt scroll-axis-lock: none today as a low-risk progressive enhancement, as non-supporting engines simply maintain standard gesture locking. For optimal control, scope the rule strictly to 2D viewports combined with overscroll-behavior: contain rather than applying it globally across document roots.
