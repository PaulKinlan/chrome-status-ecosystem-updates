# Joint Iteration

> **Report Week:** 2026-W41 | **Milestone:** Chrome 153 | **Category:** Enabled by default

## Overview

A TC39 proposal to synchronise the advancement of multiple iterators, often called zip.

## Ecosystem Status

- **Momentum:** High (280 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Positive
- **Executive Take:** Joint Iteration has progressed to Stage 4 at TC39 and adds the long-awaited native \`Iterator.zip()\` and \`Iterator.zipKeyed()\` helpers to JavaScript. With Firefox shipping support in version 148, Chrome enabling it by default in version 153, and WebKit landing support in Safari Technology Preview, cross-engine consensus is virtually unanimous. The feature fulfills a core ergonomic gap in the language's native iteration toolkit without requiring heavy utility libraries.

### Recommendations
- Actionable Advice: Teams can begin adopting \`Iterator.zip\` and \`Iterator.zipKeyed\` today using \`core-js\` polyfills for backward compatibility while targeting modern evergreen engines natively. Ensure unit tests verify mode behaviors (such as handling uneven iterable lengths with padding) before deploying to production.
- Shipping enabled by default in Chrome 153. Developers can begin adopting in production with progressive feature detection.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
