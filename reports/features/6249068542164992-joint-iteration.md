# Joint Iteration

> **Report Week:** 2026-W39 | **Milestone:** Chrome 153 | **Category:** Enabled by default

## Overview

A TC39 proposal to synchronise the advancement of multiple iterators, often called zip.

## Ecosystem Status

- **Momentum:** High (170 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Positive
- **Executive Take:** Joint Iteration (\`Iterator.zip\` and \`Iterator.zipKeyed\`) has achieved TC39 Stage 4 status and ships enabled by default in Chromium browsers starting in Chrome 153. It introduces native multi-iterable synchronization into the standard library, filling a long-standing language ergonomics gap previously addressed by utility libraries like Lodash. Engine consensus is fully aligned, with Mozilla (Gecko) and WebKit (JavaScriptCore) actively tracking implementation without contention.

### Recommendations
- Actionable Advice: Teams can safely adopt \`Iterator.zip\` and \`Iterator.zipKeyed\` in production by including polyfills such as \`core-js\` (v3.50.0+) to support non-Chromium environments. Avoid deploying unpolyfilled native invocations in multi-engine web applications until Safari and Firefox complete their implementations.
- Shipping enabled by default in Chrome 153. Developers can begin adopting in production with progressive feature detection.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
- Verified community discussion on Twitter / X: "Chrome for Developers (@ChromiumDev) on X" (0 points, 0 comments).
