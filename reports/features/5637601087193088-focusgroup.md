# Focusgroup

> **Report Week:** 2026-W37 | **Milestone:** Chrome 150 | **Category:** Enabled by default

## Overview

Gives authors the ability to declaratively give composite widgets arrow key navigation, a guaranteed tab stop, and last-focused memory, replacing hand-coded roving tabindex scripts.
Example:
<div focusgroup="toolbar wrap" aria-label="Formatting">
  <button>Bold</button>
  <button>Italic</button>
  <button>Underline</button>
</div>

### Motivation

By providing this primitive built-in the browser, authors will be able to provide this functionality without relying on custom solutions that often lead to a lack of consistency, accessibility and interoperability.

## Ecosystem Status

- **Momentum:** High (250 points)
- **Standards Alignment:** Partial Multi-Engine Interest
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** The `focusgroup` attribute is a major ergonomics upgrade transitioning into mainstream web engines, shipping enabled by default in Chrome 150 to replace hand-crafted roving `tabindex` boilerplate with native declarative arrow-key navigation. The feature has evolved through the Open UI Community Group and WHATWG PR #11723 into a scoped, accessibility-conscious model designed to guarantee entry tab stops and last-focused memory. Cross-browser consensus is actively solidifying, with Mozilla officially positive and WebKit reviewing device-independence and testing constraints.

### Recommendations
- Actionable Advice: Adopt `focusgroup` as a progressive enhancement today by pairing the HTML markup with community polyfills (such as `@doeixd/scoped-focusgroup-polyfill` or `@microsoft/focusgroup-polyfill`) to ensure consistent roving focus across all engines. Always verify that composite containers retain required ARIA roles and labels for assistive technologies until semantic role inference is universally standardized.
- Shipping enabled by default in Chrome 150. Developers can begin adopting in production with progressive feature detection.
