# Iterator Join

> **Report Week:** 2026-W40 | **Milestone:** Chrome 153 | **Category:** Enabled by default

## Overview

A TC39 proposal to add to JavaScript a means to concatenate the contents of an iterator into a string. The \`join()\` method of Iterator instances is similar to \`Array.prototype.join()\`: it returns a string that is the concatenation of all elements produced by the iterator, separated by commas or a specified separator string.

## Ecosystem Status

- **Momentum:** High (340 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Positive
- **Executive Take:** Iterator Join (\`Iterator.prototype.join()\`) extends the JavaScript Iterator Helper suite by allowing iterators to concatenate their emitted values directly into a string without allocating an intermediate array. The proposal enjoys strong cross-vendor consensus across TC39, having shipped by default in Chrome 153 while implementations in Firefox and WebKit have reached completion. It significantly improves ergonomics and memory performance when formatting streams, generator output, or collection slices.

### Recommendations
- Actionable Advice: Teams working with large data sets or generator pipelines can adopt \`iterator.join()\` immediately using polyfills like \`core-js\` or fallback feature checks (\`iterator.join?.() ?? iterator.toArray().join()\`). For untranspiled client-side code, wait until the feature hits stable baseline availability across all Safari and Firefox release channels before relying on it natively.
- Shipping enabled by default in Chrome 153. Developers can begin adopting in production with progressive feature detection.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- Community package available: \[es-iterator-helpers\](https://www.npmjs.com/package/es-iterator-helpers) (v1.4.0) for progressive enhancement.
