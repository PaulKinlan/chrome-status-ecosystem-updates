# CSS Symbols()

> **Report Week:** 2026-W42 | **Milestone:** Chrome 155 | **Category:** Enabled by default

## Overview

The CSS symbols() function lets authors define a counter style inline instead of first declaring a named @counter-style at-rule. It builds an anonymous counter style from a list of string symbols plus an optional counting system (cyclic, numeric, alphabetic, symbolic, or fixed), and is accepted as the counter style in list-style-type, the list-style shorthand, and counter() / counters().

### Motivation

Defining a custom list marker in CSS today requires authoring a named  @counter-style  rule and referencing it by name, which is needlessly verbose for one-off, anonymous markers. The symbols() function lets authors define the same counter style inline, without inventing or managing a global name. It works wherever a counter style is accepted, specifically in list-style-type and the counter()/counters() functions. Gecko has supported symbols() since 2015, but Blink and WebKit have not, so this addresses an important interoperability gap.

- **Momentum:** Moderate (footprint 190 points, ranked against this week's features because too few have an earlier number to work out a change)
- **Standards Alignment:** Multi-Engine Consensus
- **Sentiment:** Positive
- **Executive Take:** The CSS symbols() function closes a decade-long cross-engine interoperability gap by enabling authors to construct inline, anonymous counter styles directly inside properties like list-style-type and counter() without declaring global @counter-style rules. Long an exclusive feature in Mozilla Gecko since 2015, the API has reached cross-vendor convergence with Chromium shipping it by default in Chrome 155 and WebKit landing support enabled by default. Developer reception is enthusiastically positive as it removes unnecessary global-scope rule pollution for one-off and component-level markers.

### Recommendations
- Actionable Advice: Teams can begin adopting symbols() immediately using progressive enhancement by declaring traditional list markers first or guarding declarations with @supports (list-style: symbols('')). Production environments targeting broader or slower-updating client footprints should retain fallback counter configurations until current updates propagate fully across mobile and desktop installs.
- Shipping enabled by default in Chrome 155. Developers can begin adopting in production with progressive feature detection.
- Standards Activity (WebKit): Latest discussion from @fantasai: "Proposing to mark this as "Support" in 1 week unless there are objections...."
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
