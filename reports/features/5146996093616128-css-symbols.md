# CSS Symbols()

> **Report Week:** 2026-W41 | **Milestone:** Chrome 155 | **Category:** Enabled by default

## Overview

The CSS symbols() function lets authors define a counter style inline instead of first declaring a named @counter-style at-rule. It builds an anonymous counter style from a list of string symbols plus an optional counting system (cyclic, numeric, alphabetic, symbolic, or fixed), and is accepted as the counter style in list-style-type, the list-style shorthand, and counter() / counters().

### Motivation

Defining a custom list marker in CSS today requires authoring a named  @counter-style  rule and referencing it by name, which is needlessly verbose for one-off, anonymous markers. The symbols() function lets authors define the same counter style inline, without inventing or managing a global name. It works wherever a counter style is accepted, specifically in list-style-type and the counter()/counters() functions. Gecko has supported symbols() since 2015, but Blink and WebKit have not, so this addresses an important interoperability gap.

- **Momentum:** High (353 points)

- **Executive Take:** CSS symbols() provides a streamlined syntax for defining inline, anonymous counter styles directly inside properties like list-style-type without the boilerplate of declaring global @counter-style rules. Long an outlier supported exclusively in Firefox since 2015, the API is reaching major cross-engine momentum with Chromium shipping support enabled by default in Chrome 155. Engine consensus is now unified as WebKit has formally signaled support and opened implementation tracking, leaving full cross-browser Baseline availability within reach.

### Recommendations
- Actionable Advice: Adopt symbols() as a progressive enhancement today by declaring a standard list-style-type fallback immediately before the symbols() rule, or gate modern list styles behind @supports (list-style: symbols('•')). Until WebKit completes its rollout to stable Safari releases, ensure critical numbering and navigation retain accessible, readable fallbacks.
- Shipping enabled by default in Chrome 155. Developers can begin adopting in production with progressive feature detection.
- Standards Activity (WebKit): Latest discussion from @fantasai: "Proposing to mark this as "Support" in 1 week unless there are objections...."
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
