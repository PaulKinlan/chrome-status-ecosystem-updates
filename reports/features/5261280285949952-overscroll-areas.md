# Overscroll Areas

> **Report Week:** 2026-W43 | **Milestone:** Chrome 157 | **Category:** Origin trial

## Overview

This feature adds a set of primitives to allow elements to anchor to overscroll areas of other elements. It further allows these elements to be revealed with swipe gestures, similar to scrollers.

### Motivation

The web provides a rich set of animation properties and tie-ins to scrolling. What appears to be missing from the set is gesture interaction that allows content to be moved around in response to user swiping on the screen. For example, things like sidebar menu or pull to refresh are awkward to express today without script. Notably, it is possibly to polyfill some of these behaviors with Scroll Driven Animations and Snap Points, but the implementation requires insight and an in-depth understanding of these features behave.

## Ecosystem Status

- **Momentum:** Emerging (footprint 105 points, ranked against this week's features because too few have an earlier number to work out a change)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** Overscroll Areas (originating under Declarative Overscroll Actions in Open UI) introduces declarative primitives allowing elements to anchor beyond scroller boundaries to support swipeable drawers, sidebars, and pull-to-refresh interactions without custom JavaScript touch listeners. The proposal is currently moving through early specification at the CSS Working Group and is entering an experimental Origin Trial in Chromium. Other major browser vendors have not yet committed to implementations or published official signals, leaving the feature in early exploratory stages.

### Recommendations
- Actionable Advice: Teams should treat Overscroll Areas as experimental and avoid using it in production without full fallback patterns. Developers interested in native gesture design should evaluate the Origin Trial in Chromium, provide UX feedback to the Open UI and ARIA issue trackers, and ensure drawer and action menus remain fully operable via standard activatable buttons and keyboard controls.
- In active Origin Trial in Chrome 157. Validate API ergonomics in staging/pilot environments before general availability.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
