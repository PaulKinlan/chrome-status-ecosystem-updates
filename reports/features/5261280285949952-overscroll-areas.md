# Overscroll Areas

> **Report Week:** 2026-W45 | **Milestone:** Chrome 157 | **Category:** Origin trial

## Overview

This feature adds a set of primitives to allow elements to anchor to overscroll areas of other elements. It further allows these elements to be revealed with swipe gestures, similar to scrollers.

### Motivation

The web provides a rich set of animation properties and tie-ins to scrolling. What appears to be missing from the set is gesture interaction that allows content to be moved around in response to user swiping on the screen. For example, things like sidebar menu or pull to refresh are awkward to express today without script. Notably, it is possibly to polyfill some of these behaviors with Scroll Driven Animations and Snap Points, but the implementation requires insight and an in-depth understanding of these features behave.

## Ecosystem Status

- **Momentum:** Moderate (+50 points since 2026-10-12; footprint 175 points)
- **Standards Alignment:** Chromium-Led
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** Overscroll Areas (incubating as Declarative Overscroll Actions in Open UI and advancing toward CSS Overscroll Behavior Module Level 2) introduces declarative primitives for gesture-driven UI patterns like drawer menus and bottom sheets. Currently advancing through Chromium prototyping and planned Origin Trials, the proposal seeks to offload swipe-to-reveal physics directly to compositor threads without complex JavaScript workarounds. However, formal cross-engine consensus remains at a very early stage, with neither Safari nor Firefox yet committing to an official stance.

### Recommendations
- Actionable Advice: Teams should treat Overscroll Areas purely as an experimental prototype rather than adopting it in production pipelines. Developers interested in swipe gestures and bottom sheets should test prototypes behind Chromium flags or Origin Trials while ensuring production designs rely on progressive enhancement with keyboard-accessible trigger buttons and standard dialog elements.
- In active Origin Trial in Chrome 157. Validate API ergonomics in staging/pilot environments before general availability.
- Non-Chromium browser engines (WebKit/Gecko) have not formally signaled support. Wrap calls in conditional feature checks.
- No verified standalone runtime polyfill available; design progressive enhancement fallbacks for non-supporting browsers.
