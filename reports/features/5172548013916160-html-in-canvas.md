# HTML-in-canvas

> **Report Week:** 2026-W44 | **Milestone:** Chrome 157 | **Category:** Enabled by default

## Overview

HTML-in-canvas enables customizing the rendering of html using canvas with new primitives to manage canvas layout, drawing capabilities, rendering events for DOM-to-canvas synchronization, and geometry update capabilities for canvas-to-DOM synchronization.

### Motivation

High-performance web applications rely on &lt;canvas&gt; for control over rendering that goes beyond standard HTML/CSS. However, by using &lt;canvas&gt;, they lose all the rich, built-in features of the web platform, including: \* Advanced formatting, such as styled multi-line text. \* Interactivity, such as copy&paste, forms, and text selection. \* Accessibility. This forces a bad trade-off: developers must either re-implement these fundamental browser features in JS, or simply not provide them, resulting in a sub-par, inaccessible user experience.

## Ecosystem Status

- **Momentum:** High (footprint 1732 points, ranked against this week's features because too few have an earlier number to work out a change)
- **Standards Alignment:** Partial Multi-Engine Interest
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** HTML-in-canvas introduces native primitives for rendering DOM subtrees directly into 2D, WebGL, and WebGPU contexts, bridging long-standing accessibility and interactive text limitations in canvas-driven applications. Chromium is aggressively advancing and shipping the feature, but broader standardization remains an active work-in-progress across the WHATWG and WICG. Developer interest is strong among graphics and 3D web creators, yet multi-engine interoperability is still incomplete.

### Recommendations
- Actionable Advice: Teams building rich canvas or WebGPU applications should evaluate HTML-in-canvas behind flags or via targeted prototypes, particularly for UI-heavy 3D experiences. However, production architectures must avoid hard dependencies on the API and should maintain traditional DOM overlays or polyfill fallbacks until cross-browser consensus solidifies.
- Shipping enabled by default in Chrome 157. Developers can begin adopting in production with progressive feature detection.
