# HTML-in-canvas

> **Report Week:** 2026-W45 | **Milestone:** Chrome 157 | **Category:** Enabled by default

## Overview

HTML-in-canvas enables customizing the rendering of html using canvas with new primitives to manage canvas layout, drawing capabilities, rendering events for DOM-to-canvas synchronization, and geometry update capabilities for canvas-to-DOM synchronization.

### Motivation

High-performance web applications rely on &lt;canvas&gt; for control over rendering that goes beyond standard HTML/CSS. However, by using &lt;canvas&gt;, they lose all the rich, built-in features of the web platform, including: \* Advanced formatting, such as styled multi-line text. \* Interactivity, such as copy&paste, forms, and text selection. \* Accessibility. This forces a bad trade-off: developers must either re-implement these fundamental browser features in JS, or simply not provide them, resulting in a sub-par, inaccessible user experience.

## Ecosystem Status

- **Momentum:** High (+419 points since 2026-10-12; footprint 1769 points)
- **Standards Alignment:** Partial Multi-Engine Interest
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** HTML-in-canvas has shipped enabled by default in Chrome 157, providing long-awaited primitives like \`drawElementImage\` and geometry updates to render live, accessible DOM subtrees directly inside 2D, WebGL, and WebGPU canvas pipelines. The developer ecosystem has moved rapidly with early integration into graphics engines like Babylon.js and PixiJS. Cross-browser consensus is developing, with WebKit signaling support for the immediate-mode API design while Gecko continues evaluating privacy edge-cases alongside active WPT test synchronization.

### Recommendations
- Actionable Advice: Teams building WebGL, WebGPU, or canvas-heavy applications should adopt HTML-in-canvas progressively by feature-detecting the \`content="drawable"\` canvas attribute. Maintain fallback approaches—such as floating DOM overlays or SVG-based polyfills—for non-Chromium users until baseline multi-engine implementation is reached.
- Shipping enabled by default in Chrome 157. Developers can begin adopting in production with progressive feature detection.
