# HTML-in-canvas

> **Report Week:** 2026-W42 | **Milestone:** Chrome 157 | **Category:** Enabled by default

## Overview

HTML-in-canvas enables customizing the rendering of html using canvas with new primitives to manage canvas layout, drawing capabilities, rendering events for DOM-to-canvas synchronization, and geometry update capabilities for canvas-to-DOM synchronization.

### Motivation

High-performance web applications rely on &lt;canvas&gt; for control over rendering that goes beyond standard HTML/CSS. However, by using &lt;canvas&gt;, they lose all the rich, built-in features of the web platform, including: \* Advanced formatting, such as styled multi-line text. \* Interactivity, such as copy&paste, forms, and text selection. \* Accessibility. This forces a bad trade-off: developers must either re-implement these fundamental browser features in JS, or simply not provide them, resulting in a sub-par, inaccessible user experience.

## Ecosystem Status

- **Momentum:** High (footprint 1350 points, ranked against this week's features because too few have an earlier number to work out a change)
- **Standards Alignment:** Partial Multi-Engine Interest
- **Sentiment:** Cautiously Optimistic
- **Executive Take:** HTML-in-canvas bridges high-performance 2D, WebGL, and WebGPU canvas contexts with native browser capabilities like accessibility, styled multiline text, and built-in form interactivity, reaching enabled-by-default status in Chromium 157. While Chromium has rapidly pushed the feature through origin trials and WHATWG pull requests, full cross-engine consensus is still developing as API shape ergonomics and security boundaries are finalized.

### Recommendations
- Actionable Advice: Teams building rich creative tooling, games, or data visualizers should evaluate the API behind flags or origin trials to test live DOM text and UI within WebGL and WebGPU scenes. However, because Firefox and Safari have not yet shipped stable implementations, production applications should gate this feature behind progressive enhancement and avoid making it a hard requirement for core UI.
- Shipping enabled by default in Chrome 157. Developers can begin adopting in production with progressive feature detection.
